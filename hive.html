The Problem

You spawn 3 agents to build a feature. One uses camelCase, one uses snake_case, one invents a third convention. They overwrite each other's work. Nobody knows what was decided or why. Sound familiar?

Without Hive: Agents work in isolation → naming conflicts → duplicate work → silent overwrites → inconsistent output → manual cleanup

With Hive: Orchestrator sets conventions → agents validate before committing → conflicts surface immediately → decisions are recorded → output is consistent

How It Works

Four coordination primitives that reduce multi-agent consensus to "read the spec and follow it." The orchestrator front-loads everything before spawning agents.

① Conventions

Immutable rules with real-time validation. Set naming patterns, error shapes, API styles — agents validate proposed values before committing. Violations are caught automatically with suggested fixes. Once set, conventions cannot be changed within a session.

Set · Validate · List

② Shared State

A collaborative key-value store with namespace protection. Agents publish interfaces under their own prefix, read shared context, and append to collaborative lists. Built-in conflict prevention ensures concurrent writers never silently overwrite each other.

Write · Read · Append

③ Decisions

Structured audit trail of implementation choices. Every agent records what they decided and why — prevents re-litigation, provides context for future sessions. Searchable, timestamped, attributed.

Record · Search · Audit

④ Conflicts

Structured issue tracking within a session. When an agent detects an inconsistency — a naming clash, a missing interface, a broken contract — they raise it formally. The orchestrator resolves with explanation.

Raise · Resolve · Track

Convention Validation in Action

The killer feature. Agents validate proposed names against established patterns before committing — violations get caught with suggested fixes, not after the PR is up.

1
Orchestrator sets the rules
Naming conventions, casing patterns, and scope boundaries are established before any agent starts working. Rules are immutable once set.
2
Agents validate before naming
Every proposed identifier is checked against conventions in real-time. No guessing, no hoping for the best.
3
Violations caught with automatic fixes
A camelCase name in a snake_case scope? Caught instantly with the correct transformation suggested. The agent fixes it before writing any code.
✓ Consistent output
All agents follow the same conventions — snake_case stays snake_case, component naming stays uniform across the entire codebase
✗ No more post-hoc cleanup
Violations caught at write-time, not in code review. No PRs full of naming inconsistencies to fix by hand

Capabilities

Built for real multi-agent workflows. Every capability solves a problem we hit building production agent systems.

🔤 Intelligent Casing Detection

Automatically detects and validates snake_case, camelCase, PascalCase, and UPPER_SNAKE. Decomposes compound identifiers, checks every segment, and suggests the correct transformation — no manual regex configuration needed.

⏱️ Session Scoping

Every coordination session has a configurable TTL — auto-expiring so stale data never accumulates. Sessions stay clean and ephemeral. Extend active sessions dynamically when work runs long.

📋 Batch Validation

Validate multiple proposed values in a single call. Check an entire interface contract — method names, property keys, module names — all at once before writing any code. Scope-aware routing ensures the right rules apply.

📡 Agent Lifecycle Tracking

Know which agents started, which completed, and which went silent. The orchestrator gets full visibility into spawned work without manual polling — enabling verification that all delegated tasks actually executed.

🎯 Front-Load, Then Verify

The recommended orchestrator pattern: establish ALL conventions and shared context up front, spawn agents that read-and-follow, then verify output against the contract. Turns distributed consensus into a deterministic workflow.

📜 Full Audit Trail

Every action in a session is logged — conventions established, validations performed, conflicts raised, decisions recorded. Filterable and paginated. Ready for post-mortem analysis and compliance review.

The Orchestrator Pattern

The recommended workflow that eliminates coordination failures. Front-load everything, validate output.

Before Spawn
  • → Create coordination session
  • → Set ALL naming conventions
  • → Share interface contracts
  • → Define scope boundaries
During Work
  • → Agents join and read conventions
  • → Validate names before committing
  • → Publish output to own namespace
  • → Raise conflicts when blocked
After Completion
  • → Review agent outputs
  • → Check for unresolved conflicts
  • → Verify all agents completed
  • → Seal session for audit
