◆ Sirius Hive

The coordination bus that turns multi-agent chaos into structured collaboration. Conventions with real-time validation, shared state, decision audit, and conflict resolution — all session-scoped and zero-config.

View on GitHub → How It Works ↓

The Problem

You spawn 3 agents to build a feature. One uses camelCase, one uses snake_case, one invents a third convention. They overwrite each other's work. Nobody knows what was decided or why. Sound familiar?

Without Hive: Agents work in isolation → naming conflicts → duplicate work → silent overwrites → inconsistent output → manual cleanup

With Hive: Orchestrator sets conventions → agents validate before committing → conflicts surface immediately → decisions are recorded → output is consistent

How It Works

Four coordination primitives that reduce multi-agent consensus to "read the spec and follow it." The orchestrator front-loads everything before spawning agents.

① Conventions

Immutable rules with real-time validation. Set naming patterns, error shapes, API styles — agents check proposed values before committing. Violations return the exact fix. Once set, conventions cannot be changed within a session.

hive_convention_set · hive_convention_check

② Scratchpad

Shared key-value store with namespace protection. Agents publish interfaces under their own prefix, read shared context, append to collaborative lists. Supports if_not_exists to prevent overwrites.

hive_scratch_write · hive_scratch_read · hive_scratch_append

③ Decisions

Structured audit trail of implementation choices. Every agent records what they decided and why — prevents re-litigation, provides context for future sessions. Searchable, timestamped, attributed.

hive_decision_record

④ Conflicts

Structured issue tracking within a session. When an agent detects an inconsistency — a naming clash, a missing interface, a broken contract — they raise it formally. The orchestrator resolves with explanation.

hive_conflict_raise · hive_conflict_resolve · hive_conflict_list

Convention Validation in Action

The killer feature. Agents validate proposed names against established patterns before committing — violations get caught with suggested fixes, not after the PR is up.

// Orchestrator establishes naming convention before spawning agents
hive_convention_set(
  session_id = "sess_react_build",
  category = "casing",
  rule = "snake_case for all Python identifiers",
  scope = "backend"
)

// Agent checks before naming a function
hive_convention_check(
  session_id = "sess_react_build",
  category = "casing",
  proposed = "getUserProfile"
)

// Response — caught the violation with a fix:
{
  "status": "conflict",
  "convention": "snake_case for all Python identifiers",
  "suggested_fix": "get_user_profile",
  "scope": "backend"
}
✓ Passes validation
get_user_profile, fetch_api_data, build_response_body
✗ Caught by validation
getUserProfile, FetchAPIData, BUILD_RESPONSE

Features

Built for real multi-agent workflows. Every feature solves a problem we hit building production agent systems.

🔤 Casing Heuristics

Auto-detects and validates snake_case, camelCase, PascalCase, and UPPER_SNAKE. Decomposes compound identifiers, checks every segment, and suggests the correct transformation. No regex config needed.

⏱️ Session Scoping

Every Hive session has a 24-hour TTL by default. Sessions auto-expire, keeping state ephemeral. No stale coordination data accumulating. Extend TTL on active sessions when work runs long.

📋 Batch Validation

Check multiple proposed values in a single call with hive_convention_check_batch. Returns per-value pass/fail with scope routing — validate an entire interface contract before writing any code.

📡 Agent Checkin

Lifecycle signals: started, completed, blocked. The orchestrator sees which agents checked in and which went silent. Auto-joins the session on first checkin. Enables verification that all spawned work actually ran.

🎯 Orchestrator Workflow

Front-load ALL conventions and shared context to the scratchpad BEFORE spawning agents. Agents join, read the snapshot, and work. Turns distributed consensus into a simple read-and-follow pattern.

📜 Event History

Full audit log of every action in a session — conventions set, checks performed, conflicts raised, decisions made. Filterable by event type and limited for pagination. Post-mortem ready.

The Orchestrator Pattern

The recommended workflow that eliminates coordination failures. Front-load everything, validate output.

Before Spawn
  • → Create Hive session
  • → Set ALL conventions
  • → Write shared types to scratchpad
  • → Include session_id in each task prompt
During Work
  • → Agent joins, gets full snapshot
  • → Checks conventions before naming
  • → Writes output to own namespace
  • → Raises conflicts if blocked
After Completion
  • → Read scratchpad outputs
  • → Check conflict_list for unresolved
  • → Verify checkin count matches spawns
  • → Seal session for audit

Deploy Your Way

Same 18 MCP tools across all deployment tiers. Agents never know which tier they're hitting. Switch without changing agent code.

🖥️ Embedded

In-process MCP server. No network, no containers. Clone, install, add to your MCP config. Data lives in memory — perfect for single-machine development.

HIVE_BACKEND=memory

🐳 Self-Hosted

Docker container with HTTP API + MCP adapter. Multi-machine shared state, persistent storage, team coordination. Your infrastructure, your data, your rules.

docker run -p 8200:8200 siriusmcp/hive

☁️ Hosted

Managed service at hive.siriusmcp.com. Zero ops, instant setup, API key auth, multi-tenant isolation. We handle uptime, you handle building.

HIVE_BACKEND=hosted HIVE_API_KEY=sh_live_...

Quick Start

# Install

# Add to your MCP config (Cursor, Claude Code, Windsurf, etc.)

    "command": "python3",
    "args": ["-m", "sirius_hive.mcp"],
    "env": { "HIVE_BACKEND": "memory" }
