◆ Sirius Flow

Project state and work continuity. One tool call at session start gives the agent everything — what's done, what's next, what was decided, and where to resume.

The Problem

Agents lose all context between sessions. Every new chat starts from zero — re-reading files, re-discovering state, re-making decisions. Flow fixes this.

One-Call Cold Start

flow_session_start returns the full project state: last checkpoint, pending handoffs, task list, recent decisions, and what to do next.

Dependency DAG

Tasks have dependencies. Completing one automatically unblocks its dependents. The agent always knows what's ready to work on.

Dual Continuity

Checkpoints for machine resumption (exact state). Handoffs for agent briefing (human-readable context). Different purposes, both essential.

Suite Awareness

Flow signals when Memory should be updated and when Hive could parallelize. No coupling — just helpful hints the agent can act on.

Session Lifecycle

// Session starts — one call, full context
flow_session_start(project_id, agent_id="me")
→ { task_summary, next_task, last_checkpoint, pending_handoffs, suite_hints }

// Work — task updates unblock dependents
flow_task_update(task_id, status="completed", artifacts=["PR #12"])
→ { unblocked: ["task-uuid-now-ready"] }

// Session ends — atomic checkpoint + handoff
flow_session_end(project_id, summary="Built auth layer", next_actions=[...])
→ { percent_complete: 67.5, promote_to_memory: [...] }
