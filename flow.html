◆ Sirius Flow

Project state and work continuity. One tool call at session start gives the agent everything it needs — what's done, what's next, what was decided, and exactly where to resume. No re-reading. No re-discovery. No lost work.

The Problem

Every new chat session starts from absolute zero. The agent re-reads files, re-discovers project state, re-makes decisions that were already settled, and often contradicts work done in prior sessions. Context doesn't carry forward — it evaporates.

Session Amnesia

An agent builds half a feature, the session ends, the next one starts fresh. All progress tracking, decision context, and file locations — gone.

Decision Replay

The same architectural choice gets re-debated across sessions. Without a record of what was decided and why, agents oscillate between approaches.

No Handoff Protocol

When a different agent or session picks up the work, there's no structured briefing — just a bare project directory and hope.

The Solution

Flow is the project management layer for agents — task-scoped, noisy when active, archived when done. It tracks where things live, what's complete, what's next, and ensures seamless transitions between sessions.

One-Call Cold Start

flow_session_start returns the full project snapshot in a single call: last checkpoint, pending handoffs, task list with readiness, recent decisions, and suite hints. Zero warm-up time.

Dependency DAG

Tasks declare dependencies. Flow builds a directed acyclic graph with cycle detection. Completing a task triggers an unblocking cascade — dependents automatically become ready.

Dual Continuity

Checkpoints save machine-resumable state (exact variables, file positions). Handoffs create agent-readable briefings (context, decisions, what's pending). Different purposes, both essential.

Suite Awareness

suite_hints signals when Memory should be updated and when Hive could parallelize. No coupling — just structured hints the agent can act on or ignore.

Session Lifecycle

The complete work loop — cold start to clean finish — in three calls.

// 1. Cold start — one call, full context
result = flow_session_start(project_id="proj-auth-layer", agent_id="agent-7")
→ {
  task_summary: { total: 8, completed: 3, in_progress: 1, blocked: 2, ready: 2 },
  next_task: { id: "task-005", title: "Implement JWT refresh", priority: 1 },
  last_checkpoint: { saved_at: "2026-08-11T14:30:00Z", data: {...} },
  pending_handoffs: [{ from: "agent-3", summary: "Auth DB schema is done..." }],
  suite_hints: { parallel_tasks: 2, promote_pending: 1 }
}

// 2. Work — task completion triggers unblocking cascade
result = flow_task_update(task_id="task-005", status="completed", artifacts=["PR #47"])
→ {
  status: "completed",
  unblocked: ["task-006", "task-007"]  // dependents now ready
}

// 3. Session ends — atomic checkpoint + handoff + metrics
result = flow_session_end(project_id="proj-auth-layer",
  summary="JWT refresh and token rotation implemented",
  next_actions=["Integration tests", "Update API docs"])
→ {
  percent_complete: 62.5,
  promote_to_memory: [
    { content: "Auth uses RS256 JWT with 15min access / 7day refresh",
      entities: ["auth", "jwt"], category: "project" }
  ]
}

Features

Purpose-built primitives for tracking work across agent sessions.

Dependency Resolution

Full DAG with topological ordering and cycle detection. flow_task_add validates dependency chains — circular dependencies are rejected immediately with the cycle path reported.

Unblocking Cascade

Completing a task returns the list of newly-ready dependents. The agent doesn't traverse the graph — Flow does the work and hands back actionable task IDs.

Decision Tracking

Every architectural and implementation choice is recorded with reasoning and context. Decisions support supersession — a new decision explicitly replaces an old one, maintaining the audit trail.

Atomic Session End

flow_session_end saves checkpoint + creates handoff in a single atomic call. No half-states. The next session either gets everything or nothing.

Memory Promotion

When a project completes or a session ends, Flow returns pre-formatted facts ready for sirius_fact_add. Lessons learned flow automatically into durable memory.

Project Completion

flow_project_complete archives all operational state and promotes durable learnings. Work data disappears cleanly — only wisdom persists.

Deployment

Same 15 tools at every scale. Start embedded, graduate to hosted — zero code changes.

Embedded

In-process MCP server. Set FLOW_BACKEND=memory and run. State lives in-memory — perfect for single sessions, development, and testing. Zero dependencies.

Self-Hosted

SQLite or Postgres backend. Persistent state across restarts. Deploy alongside your agent infrastructure. Full control over your data.

Hosted

flow.siriusmcp.com — managed service. Multi-tenant, API-key auth, automatic backups. Same MCP tools, no infrastructure to maintain.

Design Philosophy

Noisy When Active, Gone When Done

Flow keeps every detail for the active task — file paths, step counts, blocked states, scratch notes. When the project completes, operational sludge is archived. Only lessons persist.

The Opposite of Memory

Memory is durable, curated, high-signal. Flow is ephemeral, detailed, task-scoped. Putting your Jira board into your personal notebook would pollute both. Same principle here.

Agent is the Bridge

Flow never calls other tools directly. It prepares data FOR them and signals WHEN to use them. promote_to_memory is pre-formatted for sirius_fact_add — the agent makes the call.
