◆ Sirius Flow

Project state and work continuity. One tool call at session start gives the agent everything it needs — what's done, what's next, what was decided, and exactly where to resume. No re-reading. No re-discovery. No lost work.

The Problem

Every new chat session starts from absolute zero. The agent re-reads files, re-discovers project state, re-makes decisions that were already settled, and often contradicts work done in prior sessions. Context doesn't carry forward — it evaporates.

Session Amnesia

An agent builds half a feature, the session ends, the next one starts fresh. All progress tracking, decision context, and file locations — gone.

Decision Replay

The same architectural choice gets re-debated across sessions. Without a record of what was decided and why, agents oscillate between approaches.

No Handoff Protocol

When a different agent or session picks up the work, there's no structured briefing — just a bare project directory and hope.

The Solution

Flow is the project management layer for agents — task-scoped, noisy when active, archived when done. It tracks where things live, what's complete, what's next, and ensures seamless transitions between sessions.

Instant Context Recovery

A single call at session start returns the full project snapshot: last checkpoint, pending handoffs, task readiness, recent decisions, and coordination hints. Zero warm-up time — the agent picks up exactly where the last session left off.

Smart Task Ordering

Tasks declare dependencies and Flow resolves them into a directed acyclic graph. Completing a task triggers an automatic unblocking cascade — downstream work becomes ready without the agent traversing the graph manually.

Dual Continuity

Checkpoints save machine-resumable state (exact variables, file positions). Handoffs create agent-readable briefings (context, decisions, what's pending). Different purposes, both essential.

Suite Awareness

Flow signals when Memory should be updated and when Hive could parallelize independent tasks. No coupling — just structured hints the agent can act on or ignore.

The Work Loop

A complete session lifecycle in three steps — cold start, work, clean finish.

1. Cold Start

The agent opens a session. Flow returns everything: the last checkpoint, any pending briefings from previous agents, the full task list with ready/blocked status, recent architectural decisions, and signals about parallelization opportunities. One call, full context.

2. Work & Track

As the agent completes tasks, Flow updates the dependency graph. Downstream tasks automatically unblock. Decisions are recorded with reasoning. Checkpoints capture state at any point so crashes don't lose progress.

3. Clean Handoff

Session ends atomically — checkpoint saved and briefing created in one operation. The next agent or session gets a structured handoff, not a blank slate. Lessons learned are pre-formatted for promotion to durable memory.

What Flow Gives You

Purpose-built capabilities for tracking work across agent sessions.

Dependency Resolution

Full directed acyclic graph with topological ordering and cycle detection. Circular dependencies are caught immediately — before the agent starts work that can't be completed.

Unblocking Cascade

Completing a task returns the list of newly-ready dependents. The agent doesn't traverse the graph — Flow does the work and hands back the next actionable items.

Decision Tracking

Every architectural and implementation choice is recorded with reasoning. Decisions support supersession — a new decision explicitly replaces an old one, maintaining the full audit trail.

Atomic Session Management

Session wrap-up saves checkpoint and creates the handoff in a single atomic call. No half-states. The next session either gets everything or nothing — never a corrupted partial.

Memory Promotion

When a project completes, Flow returns durable learnings pre-formatted for Sirius Memory. Lessons that matter persist beyond the project. Operational details are archived.

Clean Project Completion

Projects archive all operational state and promote only wisdom. Task counts, file paths, blocked states — gone. Only decisions and patterns that inform future work survive.

Deployment

Same tools at every scale. Start embedded, graduate to hosted — zero code changes.

Embedded

In-process MCP server. State lives in-memory — perfect for single sessions, development, and testing. Zero dependencies beyond the Python package.

Self-Hosted

SQLite or Postgres backend. Persistent state across restarts. Deploy alongside your agent infrastructure. Full control over your data.

Hosted

Managed service at flow.siriusmcp.com. Multi-tenant, API-key auth, automatic backups. Same MCP tools, no infrastructure to maintain.

Design Philosophy

Noisy When Active, Gone When Done

Flow keeps every detail for the active task — file paths, step counts, blocked states, scratch notes. When the project completes, operational sludge is archived. Only lessons persist.

The Opposite of Memory

Memory is durable, curated, high-signal. Flow is ephemeral, detailed, task-scoped. Putting your Jira board into your personal notebook would pollute both. Same principle here.

Agent is the Bridge

Flow never calls other tools directly. It prepares data for them and signals when to use them. The agent always makes the final decision on what to do with Flow's output.
