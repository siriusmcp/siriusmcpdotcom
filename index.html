How It Works

Every product is a standard MCP server. Add it to your platform's config — the agent gets the tools immediately. No SDK, no wrapper library, no vendor lock-in.

1. Install

Clone the repo and install the Python package — or pull the Docker image. Each product is a single pip-installable package with zero required dependencies beyond the MCP SDK.

2. Configure

Add one entry to your platform's MCP server list. Point it at the installed module. Set a backend (in-memory, SQLite, or hosted API key). Done.

3. Use

Your agent now has the tools. Memory persists facts across sessions. Hive coordinates parallel work. Flow tracks project state. No code changes in your agent required.

Better Together

Each product works fully on its own — but when combined, they share structured signals that make multi-session workflows seamless.

Flow → Hive

When Flow detects independent tasks that can run in parallel, it signals the opportunity. The agent creates a Hive coordination session to split the work across multiple agents safely.

Flow → Memory

When a project completes, Flow surfaces the durable lessons — architectural decisions, tool preferences, patterns learned — pre-formatted so the agent can persist them to Memory in one step.

Memory → Flow & Hive

Past preferences and conventions inform new projects. Memory provides the accumulated context that shapes how Flow structures tasks and how Hive establishes conventions.

Hive → Flow

After a Hive coordination session seals, established conventions and decisions carry forward as Flow records — informing future sessions about what was agreed and why.

No product calls another directly. The agent is always the bridge. Each product remains independently functional.
