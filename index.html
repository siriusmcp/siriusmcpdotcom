Deploy Your Way

Every product supports the same progressive deployment model. Start local, scale when you need to.

🖥️ Embedded

In-process MCP server on your own machine. No network, no service, no dependencies. Clone the repo, install, run. Your data stays local.

Best for: individual developers, air-gapped environments

🐳 Self-Hosted

Docker container or dedicated server. HTTP API + MCP adapter. Multi-tenant, multi-machine shared state. Your infrastructure, your data.

Best for: teams, enterprises, on-premise requirements

☁️ Hosted Service

Managed API at *.siriusmcp.com. Zero ops, instant setup. API key authentication, multi-tenant isolation, automatic backups. We run it, you use it.

Best for: zero-ops setup, cross-team collaboration

Same MCP tools across all tiers. Agents never know which tier they're hitting. Switch tiers without changing agent code.

How It Works

Every product is an MCP server. Add it to your platform's config. The agent gets the tools immediately.

// Add to your platform's MCP config (Cursor, Claude Code, Windsurf, etc.)

{
  "mcpServers": {
    "sirius-memory": {
      "command": "python3", "args": ["-m", "sirius_memory.mcp"],
      "env": { "SIRIUS_API_KEY": "sm_live_..." }
    },
    "sirius-hive": {
      "command": "python3", "args": ["-m", "sirius_hive.mcp"],
      "env": { "HIVE_BACKEND": "memory" }
    },
    "sirius-flow": {
      "command": "python3", "args": ["-m", "sirius_flow.mcp"],
      "env": { "FLOW_BACKEND": "memory" }
    }
  }
}

Better Together

Each product works alone. When combined, they share signals that make the whole workflow seamless.

SignalFromToWhat happens
suite_hints.parallel_tasksFlowHiveFlow tells the agent when independent tasks exist — agent creates a Hive session to coordinate parallel work
promote_to_memoryFlowMemoryOn project complete, Flow returns decisions pre-formatted for Memory — agent pipes them to sirius_fact_add
sirius_contextMemoryFlow/HivePast project preferences and conventions inform new Flow projects and Hive session setup
Hive conventionsHiveFlowAfter a Hive session seals, established conventions become Flow decisions for future reference

No product calls another directly. The agent is always the bridge. This keeps each product independently functional.
