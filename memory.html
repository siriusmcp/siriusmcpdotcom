Three Layers of Memory

Each layer serves a distinct purpose, working together to give agents comprehensive, contextual recall without flooding the prompt.

Layer 1 — File Memory

Always-on identity context. User profile, project state, system preferences — injected every turn without being asked. The agent knows who you are before you speak. Budget-managed with automatic compaction at 80% capacity.

Always injected · 3000 token budget

Layer 2 — Holographic Facts

Entity-linked knowledge with trust scoring. Decisions, preferences, relationships — each fact carries confidence that evolves with feedback. Better facts surface higher. Includes contradiction detection and entity resolution.

Trust-ranked retrieval · starts at 0.7

Layer 3 — Vector Recall

Semantic search over ingested documents and past sessions. Ask a natural-language question, get the most relevant fragments — regardless of when they were stored. Hybrid search with RRF fusion for best results.

Semantic similarity · pgvector cosine

Built for Real-World Agents

Not a demo. A production memory layer designed for reliability, speed, and the messy reality of multi-session agent work.

⟳ Cross-Machine Sync

Store a fact on your laptop. See it on your server. Shared memory pool across all your agents and machines — no sync conflicts, no manual setup. One API key, every device.

△ Adaptive Trust

Facts earn trust through use. Helpful knowledge rises (+0.05). Outdated or wrong facts decay (-0.10). The system learns which memories matter — dormant facts can be resurrected with a +0.15 boost.

⊕ Scoped Directives

Standing rules that apply only when relevant. "Always use snake_case" fires in Python sessions, not markdown editing. 15+ valid scopes: python, typescript, sql, api_design, architecture, testing, and more.

↻ Offline Resilience (WAL)

Write-ahead log queues operations when the service is unreachable. Drains automatically on reconnection. No data lost, no user intervention needed. Works behind firewalls and in air-gapped environments.

◎ Budget-Managed Context

One API call assembles all layers into a token-budgeted block. L1 file memories (3000 tokens), relevant L2 facts, L3 vector hits, and active directives — all deduplicated and prioritized. No prompt overflow.

⚡ Contradiction Detection

New facts are checked against existing knowledge. Conflicts surface for human resolution — the system never silently overwrites what it knows. Resolution options: keep, supersede, or archive.

How Memory Works

Every turn follows the same three-step pattern. One call in, work happens, facts out.

①

Retrieve

Agent calls sirius_context at the start of every turn. Gets back L1 identity, relevant L2 facts, L3 vector hits, and active directives — all within token budget.

②

Work

Agent uses the context to inform its response. Probes specific entities with fact_probe. Searches for related knowledge. Follows active directives.

③

Store

Agent saves new facts (fact_add), submits trust feedback, and creates directives from corrections. Memory grows with every session.
